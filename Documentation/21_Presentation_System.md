# Responsible Control — Presentation System v0.2

Рабочий файл: [Figma Slides v0.2](https://www.figma.com/slides/4ckOw23Xz1ZuvSZUmmaPJ2/responsible_control_presentation_system_v02). Предыдущая версия: [v0.1](https://www.figma.com/slides/QxroswqVLCZD0BvSFkRwr4/responsible_control_presentation_system_v01).

Статус реализации: 55 редактируемых слайдов собраны и проверены. Первые 24 задают визуальную систему и состав MVP; следующие 31 переводят состав в конкретные solution frames. Текст, формы, placeholders и presenter notes перенесены как отдельные объекты. Локальный `.pptx` использует Noto Sans / Menlo; Figma нормализовал существующие текстовые слои в Inter, а Noto Sans добавлен в template style для следующей итерации.

## Задача

Собрать в одном Figma-файле редактируемую систему layouts, презентацию MVP и набор конкретных кадров для проектирования решений. Сначала презентация объясняет визуальную грамматику Responsible Control, затем показывает состав прототипа из [[15_MVP_Prototype]], а после задаёт будущие изображения, ракурсы и проверяемую функцию каждого решения.

> К концу просмотра участник проекта должен понимать, что именно входит в MVP, как все носители складываются в один опыт и по каким визуальным правилам система информирует без продвижения и стигмы.

Это не отдельная маркетинговая история, не портфолио-кейс и не презентация вымышленного бренда. Видимый текст берётся из vault; отсутствующие изображения обозначаются редактируемыми прямоугольниками с конкретной подписью для будущей замены.

## Что берём из общей инструкции

- формат 16:9;
- 12 колонок, равные боковые поля и модуль 8;
- ясную иерархию `тезис → материал → значение`;
- минимум композиционного декора;
- редактируемые текст, формы, таблицы и placeholders;
- набор повторяемых layouts;
- обязательную проверку каждого кадра на переносы, обрезку и наложения;
- функциональные переходы без декоративной анимации.

## Что адаптируем под Figma и проект

| Общий параметр | Решение Responsible Control |
|---|---|
| PowerPoint Slide Master и Layouts | Figma components / variants и именованные frame templates |
| PowerPoint placeholders | редактируемые текстовые и визуальные слоты внутри компонентов |
| Speaker notes | описание layout на странице библиотеки и в названии компонента; при работе в Figma Slides — notes |
| Arial / Aptos | Noto Sans и Noto Sans Mono из [[08_Visual_System]] |
| бело-серая нейтральная палитра с одним accent | тёплая проектная палитра; по умолчанию `information`, остальные сигналы только по функции |
| PowerPoint Fade / Wipe / Morph | Dissolve и Smart Animate в prototype flow; финальный кадр всегда самодостаточен |
| заполненная библиотека графиков | только пустые паттерны; числовые данные появятся после [[16_Metrics_and_Testing]] |

Нативная логика PowerPoint Master не имитируется: итоговый носитель — Figma. Если для переноса используется `.pptx`, это только промежуточный редактируемый транспорт.

## Формат и сетка

- frame: `1920 × 1080 px`;
- внешний модуль: `8 px`;
- поля: `96 px` слева и справа, `64 px` сверху и снизу;
- 12 колонок;
- gutter: `27 px`;
- рабочая колонка: `119.25 px`;
- базовые пропорции: `12/12`, `8/4`, `7/5`, `6/6`, `4/8`, full bleed;
- выравнивание преимущественно по левому краю;
- один кадр использует не более одного активного цветового сигнала.

## Visual placeholder / solution frame

Изображения пока заменяются одним типом редактируемого блока:

- фон `RC/Paper`, линия `RC/Rule`, без скругления;
- метка `VISUAL PLACEHOLDER`;
- конкретное описание будущего изображения;
- рекомендуемая пропорция;
- запрет на lifestyle, product hero и декоративный mood shot;
- для публичных материалов допустимы документальные фотографии систем, работников и городской среды с информационной подписью.

Пример подписи: `VISUAL PLACEHOLDER · фасадный фрагмент 1:1 · документальный фронтальный кадр · заменить без lifestyle-кода`.

В v0.2 placeholder становится рабочим brief и всегда содержит четыре поля:

- носитель или объект: упаковка, фасад, план, экран, карточка, badge, световой или акустический план;
- обязательный вид: `front`, `back`, `3/4`, `macro`, `plan`, `eye-level`, фиксированная контрольная камера;
- техническое условие: масштаб, объектив, высота камеры, отсутствие перспективы или mockup-сцены;
- функция кадра: какое правило, риск, действие, сравнение или участок маршрута он должен проверить.

Плейсхолдер не описывает стилистику готового решения и не подменяет дизайн. Он фиксирует минимально достаточное задание, после которого можно рисовать, моделировать или фотографировать без повторного изобретения структуры презентации.

## Layout library

| Компонент | Геометрия | Сценарий |
|---|---|---|
| `RC/Slide/Cover` | full bleed | название системы или крупного раздела |

| `RC/Slide/Statement` | 12/12 | один принцип или итог |
| `RC/Slide/OneColumn` | 12/12 | последовательный текстовый блок |
| `RC/Slide/TextVisual` | 7/5 | тезис и будущий визуальный материал |
| `RC/Slide/Comparison` | 6/6 | симметричное сравнение без победителя |
| `RC/Slide/Metric` | 4/8 | измеримый критерий с контекстом |
| `RC/Slide/DataInterpretation` | 8/4 | данные и их значение |
| `RC/Slide/Table` | 12/12 | сравнимые поля или спецификация |
| `RC/Slide/Process` | 12/12 | маршрут, процесс или timeline |
| `RC/Slide/Evidence` | 7/5 | материал и ограниченная интерпретация |

Компоненты не требуют отдельных вымышленных демонстраций: их заполненные экземпляры находятся в самой презентации. KPI и графические layouts остаются пустыми до появления данных тестирования.

## Motion в прототипе

Переходы создаются только там, где они помогают следить за последовательностью:

1. постепенное появление шагов сквозного сценария — Dissolve;
2. раскрытие семи digital-экранов — Smart Animate по маске;
3. переключение `commercial → hostile plain → Responsible Control` — Smart Animate без декоративной трансформации;
4. переход между визуальной системой и MVP — короткий Dissolve.

Каждая последовательность заканчивается полноценным статическим кадром; reduced-motion версия использует мгновенную смену.

## Проверка перед передачей

- все 55 кадров используют одну систему отступов, типов и линий;
- каждый блок [[15_MVP_Prototype]] представлен без добавленной истории, а 31 solution frame переводит его в конкретное задание на визуал;
- placeholder подписан конкретным будущим материалом;
- нет случайных переносов, обрезки, наложений и незаполненных служебных подписей;
- соседние кадры различаются силуэтом, но не правилами;
- один кадр не смешивает несколько активных сигналов;
- продукт нигде не получает hero-композицию;
- все элементы остаются редактируемыми;
- прототипные переходы не мешают статическому экспорту;
- имя файла / Figma-проекта: `responsible_control_presentation_system_v02`.

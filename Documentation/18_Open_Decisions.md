# Open Decisions

## Как пользоваться

Неизвестное не является дефектом скелета. Дефектом будет замаскировать его уверенным дизайном. До решения вопрос хранится здесь, а в прототипе используется явно обозначенная временная переменная.

## Блокирующие реальное внедрение

| Вопрос | Почему важен | Временное решение MVP |
|---|---|---|
| Юрисдикция | определяет закон, возраст, язык, лицензии и нормы | система без страны, все правовые поля — переменные |
| Перечень продуктов | влияет на риск, упаковку и каналы | три фиктивных семейства, без реального ассортимента |
| Метод оценки риска | нельзя назначить дизайном | многомерная пустая модель `R1–R4` только для UI-теста |
| Клинический контент | цена ошибки высока | утверждённые плейсхолдеры без инструкций |
| Канал каждого типа | разные формы требуют разных режимов | MVP одной лицензированной точки без on-site use |
| Возраст и eligibility | правовой и этический параметр | `AGE_MIN` и `ELIGIBILITY_RULE` |
| Цена, налог и лимиты | влияют на спрос и нелегальный рынок | вне текущего MVP |
| Право и хранение данных | определяет ID-flow | mock-проверка атрибута без сохранения личности |
| Организационный владелец | доверие зависит от стимулов | абстрактный независимый operator/regulator split |

## Блокирующие визуальную финализацию

| Вопрос | Риск | Временное решение MVP |
|---|---|---|
| Публичное имя | само имя может стать брендом или морализировать | `Responsible Control` только как кодовое имя |
| Знак системы | знак может читаться как одобрение продукта | служебная текстовая плашка с пояснением |
| Цветовой код риска | green/safe и dark/strong создают ложные смыслы | цвет только для действий; профиль риска текстом |
| Финальный шрифт | нейтральный grotesk может стать luxury-кодом | Noto Sans как доступный прототип |
| Материал упаковки | безопасность различается по продукту | три условных семейства и стандартная этикетка |
| Фото и иллюстрация | могут информировать или романтизировать | без фото в transaction layer |
| Многоязычие | меняет иерархию и размер | два тестовых языка после выбора контекста |
| Тактильные маркеры | доступность может стать отличительным trade dress | только функциональный стандартизированный набор |

## Блокирующие пространственную финализацию

- реальная площадь и поток;
- требования безопасности и хранения;
- нужен ли контроль входа для конкретного канала;
- допустимая прозрачность фасада;
- акустические нормы и конфиденциальность;
- строительные нормы доступности;
- числовые параметры света;
- допустимость нейтрального sound masking;
- формат очереди и пиковая нагрузка;
- контролируемое употребление на месте.

## Блокирующие сервис

- правовые основания отказа;
- границы клинических вопросов;
- признаки состояния, исключающего выдачу;
- экстренный и first-aid протокол;
- связь с локальными службами помощи;
- документация инцидента;
- механизм обжалования;
- подготовка и сертификация сотрудника.

## Вопросы авторской позиции

Их можно решить после просмотра скелета:

1. Должно ли рабочее понятие «антибренд» остаться публичным или только методическим?
2. Насколько видимым должен быть общественный знак относительно названия продукта?
3. Нужна ли системе одна эстетическая территория или намеренная визуальная вариативность в строгой грамматике?
4. Допустима ли вообще музыка, если она не узнаваема и нужна для privacy/accessibility?
5. Должна ли упаковка быть общей для существующих брендов алкоголя и табака в переходный период?
6. Где проходит граница между нейтральной информацией о сравнительном риске и promotion менее вредной формы?
7. Какой физический носитель лучше всего продемонстрирует MVP: pop-up точка, выставочная симуляция или digital twin?
8. Нужно ли разрабатывать публичный манифест или оставить систему в языке стандарта?

## Очерёдность решений

1. Сначала: юрисдикция, продукты, риск и каналы.
2. Затем: content ownership, ID/privacy, помощь и отказ.
3. Затем: знак, цвет, материал, свет и акустика.
4. Последними: публичное имя, коммуникационная оболочка и масштабирование.

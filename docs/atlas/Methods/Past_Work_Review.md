# PAST WORK REVIEW — реконструкция прошлой практики

[← Methods Overview]({{ site.baseurl }}/atlas/Methods/METHODS_OVERVIEW.html)

## Method Definition

### Purpose

Реконструировать прошлую практику по доступным материалам и уточнениям участников: установить исходную задачу, фактические роли и вклад, принятые решения, степень реализации, доступный результат и предел доказательства каждого кейса.

Архив и интервью не являются двумя отдельными методами. Архив даёт документальное основание, интервью или другое уточнение закрывает пробелы и восстанавливает контекст, когда это необходимо.

### Categories

- Research
- Synthesis / Analysis

### Use When

- у автора, команды или организации есть прошлые проекты, но их устройство и значение описаны неполно;
- портфолио показывает результат, но не позволяет установить роль, процесс, реализацию или ограничения;
- нужно восстановить доступные доказательства компетенции, способа работы или повторяющегося паттерна;
- воспоминания участников необходимо сопоставить с архивом и другими источниками.

### Do Not Use When

- прошлой практики ещё нет;
- вопрос касается только наблюдаемого текущего состояния и не требует реконструкции истории;
- доступных материалов и участников недостаточно даже для ограниченного вывода — в этом случае фиксируем пробел, а не достраиваем кейс;
- требуется доказать коммерческий или иной эффект, но имеются только созданные материалы без относящихся к эффекту данных.

### Required Inputs

- перечень рассматриваемых проектов и границы периода;
- доступные исходники, презентации, публикации, переписка, фотографии реализации, данные или другие материалы;
- сведения участников — если нужны для уточнения роли, контекста и пробелов;
- проектный вопрос, определяющий необходимую глубину реконструкции.

### Process

1. Сформулировать Project Question и Scope применения.
2. Собрать карту доступного архива и отметить, что каждый источник позволяет и не позволяет проверить.
3. Восстановить отдельные case records, сохраняя ссылки на основания.
4. Уточнить значимые пробелы интервью, перепиской или другими доступными источниками; не проводить интервью ради обязательного ритуала.
5. Отделить документально подтверждённое, сообщение участника, интерпретацию и неизвестное.
6. Сопоставить кейсы и сформулировать межкейсовые закономерности с пределами выборки.
7. Связать только относящиеся к делу findings с каноническими разделами Atlas.

### Expected Form of Result

- карта изученного архива;
- один или несколько reconstructed case records;
- межкейсовый синтез, если объём применения позволяет сравнение;
- ссылки на evidence, неизвестные и ограничения;
- конкретные связи с каноническими наблюдениями и решениями.

### Limitations

- воспоминание участника не равно независимому документальному подтверждению;
- авторство идеи, создание материала, принятие решения, реализация и достигнутый эффект — разные утверждения и требуют разных оснований;
- созданное не считается реализованным без подтверждения реализации;
- реализация сама по себе не доказывает коммерческий, поведенческий или репутационный эффект;
- отсутствие данных об эффекте не является доказательством неэффективности;
- прошлый кейс не автоматически описывает текущую практику;
- межкейсовый паттерн ограничен составом и качеством рассмотренных кейсов.

### Source / School

Рабочий метод реконструкции практики, объединяющий document review, case reconstruction и уточняющее интервью. Единственный внешний автор или школа не назначены. При использовании отдельной признанной процедуры интервью или анализа источников даём ссылку в конкретном Application Record.

## Application Records

Ниже — повторяемая форма. Каждое применение получает стабильный ID. Внутри одного применения может быть несколько case records, если они отвечают на общий Project Question и сопоставляются в одном синтезе.

### APP-ID — название применения

#### Рамка применения

- **Date / version:** …
- **Project Question:** …
- **Scope:** какие проекты, период и аспекты рассматриваются — …
- **Доступные источники:** …
- **Недоступные источники / участники:** …
- **Executed Process / deviations:** что сделано и чем процедура отличалась от базовой — …

#### Карта архива

| Проект / кластер | Материалы и источники | Что можно проверить | Чего установить нельзя | Статус просмотра |
|---|---|---|---|---|
| … | … | … | … | Не просмотрено / частично / просмотрено |

#### Case ID — название проекта

| Поле | Реконструированная запись | Основание и статус утверждения |
|---|---|---|
| Situation / Task | … | Ссылка; документально подтверждено / сообщение участника / интерпретация / неизвестно: … |
| Participants / Actual Role | … | … |
| Contribution | … | … |
| Key Actions / Decisions | … | … |
| What Was Actually Implemented | … | … |
| Result / Application | … | … |
| Evidence | Ссылки на конкретные материалы: … | Что именно подтверждает каждый источник и чего не подтверждает: … |
| What This Case Supports | Какое ограниченное утверждение можно использовать: … | Почему оснований достаточно в указанных пределах: … |
| What It Does Not Support | … | Недоступные данные или логическая граница: … |
| Unknowns / Limitations | … | Что могло бы уточнить запись: … |

Статус утверждения относится к конкретной записи, а не ко всему кейсу сразу. Интерпретация допустима, если обозначена как интерпретация и имеет видимое основание.

##### Условные поля — добавляются по Project Question

| Поле | Запись | Основание / ограничение |
|---|---|---|
| Research Performed | … | Что действительно проводилось и какой вопрос закрывало: … |
| Decision Chain | Наблюдение → интерпретация → решение → проявление: … | Какие переходы подтверждены, а какие реконструированы: … |
| Rejected / Unrealized Options | … | Не смешивать с принятым или реализованным результатом: … |
| Timing / Economics | … | Источник, период и релевантность Project Question: … |
| External Circumstances | … | Как ограничивают интерпретацию результата: … |
| Publication / Access Restrictions | … | Что можно показывать, цитировать или передавать: … |

Повторите карточку для каждого кейса в Scope. Полная публичная case presentation может быть отдельным Output или представлением этих материалов, но не заменяет evidence record метода.

#### Межкейсовый синтез — если применим

| Повторяющийся паттерн / вывод | Поддерживающие case records | Противоречия и ограничения выборки | Возможный Canonical Use |
|---|---|---|---|
| Способ работы / компетенция / проблема / тип результата: … | Ссылки на конкретные Case ID и evidence: … | … | Какой нормализованный finding может использовать какой раздел Atlas: … |

Сходство нескольких рассказов не автоматически доказывает устойчивую текущую практику. Для каждого общего вывода указываем, какие кейсы его поддерживают, какие противоречат и чего не хватает.

#### Результат применения и связи

- **Project Result:** кратко, что удалось реконструировать и выяснить — …
- **Result Limitations:** …
- **Canonical Use:** конкретный вывод → канонический раздел → ссылка на его нормализованную запись — …
- **Status:** запланировано / выполняется / завершено / недостаточно данных / требует дополнения / отменено — …
- **Next Step — если нужен:** …

## Граница с Audit и другими разделами

Past Work Review хранит reconstructed cases, evidence и межкейсовый рабочий синтез. [Audit]({{ site.baseurl }}/atlas/01_Audit/AUDIT_OVERVIEW.html) может хранить конкретное наблюдение о подтверждаемой практике со ссылкой на относящийся к нему Case ID. Не каждый прошлый кейс автоматически является доказательством текущего состояния.

Если применение приводит к более общему каноническому выводу — например, о повторяющемся способе работы, ценности, предложении или принципе системы, — соответствующий раздел Atlas хранит собственную нормализованную формулировку и ссылку назад. Полный case record второй раз не переписывается.
